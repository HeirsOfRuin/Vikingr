# Vikingr: the Android app

The itch.io Android download is the full game's single-file release build (`npm run build:app`: `npm run
build:single`, then that file copied to `dist-app/index.html`) inside a Capacitor WebView, the same way the
Imperator and Silk Road apps are made. It plays offline; the app keeps its saves on the phone. GitHub builds it
(`.github/workflows/android.yml`) when you ask it to, not on every push: the repository is public, and any
signed-in GitHub user can download a run's artifact. Nothing is built on your own machine.

## Getting the APK

1. On github.com, open the repository's **Actions** tab, choose **Android app**, and press **Run workflow**.
2. When it finishes (a few minutes), open that run, scroll to **Artifacts** and download **vikingr-android**.
3. Inside the zip: `vikingr.apk` when the signing secrets are set (publish this one), or `vikingr-TEST.apk` when
   they are not (try it on your own phone; never publish it: no later version can install over it).
4. Upload `vikingr.apk` to itch with only **Android** ticked. Artifacts are kept 3 days: download it the same day.

## The signing key (once)

Vikingr shares the HeirsOfRuin key with Imperator and Silk Road (made 2026-11-20, key alias `heirsofruin`). In this
repository: **Settings > Secrets and variables > Actions > New repository secret**, twice:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | the contents of `ANDROID_KEYSTORE_BASE64.txt` from the key's zip |
| `ANDROID_KEYSTORE_PASSWORD` | the contents of `ANDROID_KEYSTORE_PASSWORD.txt` |

Keep the keystore and password in a password manager: if they are lost, the published app can never be updated,
and players would have to uninstall and lose their saves. The app id `io.github.heirsofruin.vikingr` is permanent
once an APK is published.

## What is in the repository

- `capacitor.config.json`: the app id, name, web folder (`dist-app`) and background colour.
- `android/`: generated by `npx cap add android`, with two edits in `app/build.gradle`: the version code is the
  workflow's run number, so every APK installs over the last; and release builds are signed with the key from the
  workflow's environment (alias `heirsofruin`).
- `tools/android-icons.mjs`: draws the launcher icons and splash screens from `public/icons/`. Re-run it if the
  icons change.

Not proved in a cloud session (no Android SDK there): the first workflow run is the check.
